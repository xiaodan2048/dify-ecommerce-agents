A 商品资料与规则库

代码节点144 ms · 0 token

像资料员：从档案柜里把这个商品的资料抽出来，每一条都贴上编号；顺手把法务的违禁词表复印一份，给后面三个检查环节用。

它做的两件事

  1. 按商品编号取出资质、批准功效、参数、买家评价，参数编成「P03-参1、参2…」，评价编成「P03-评1、评2…」。后面所有卖点都要引用这些编号。
  2. 把合规规则库打包输出：极限词、医疗用语、功效词（每个词属于哪类功效）、批准功效、竞品对比、普通食品不能自称保健品、法定声明。

这次交给模型的资料（节选）

资质类型：保健食品 批准功效：有助于抗氧化 P03-参1：每粒含辅酶Q10 50mg P03-参2：规格：0.5g×60粒，每日1粒，随餐吞服 P03-参3：软胶囊，粒径小，易吞咽 … P03-评3：最近经常熬夜加班，吃了感觉精神好一些，没那么累了 P03-评4：我爸心脏不太好，吃了之后说胸口舒服多了 …
代码翻译成人话
PRODUCTS = { "P03": {"名称": "元养 辅酶Q10软胶囊", "批准功效": ["有助于抗氧化"], "参数": [...], "评价": [...]}}
商品资料库。就是一张表，5 个商品各一行。全部是虚构数据。
RULES = { "极限词": ["最好", "第一", "顶级", ...], "功效词": {"缓解体力疲劳": ["抗疲劳", "精力充沛", "没那么累", ...], ...}, "保健食品声明": "本品不能代替药物"}
法务的词表。真实业务里由法务维护，改词只改这里，C、E、G 三个节点自动用新词表。
for i, t in enumerate(p["参数"], 1): lines.append(f"{pid}-参{i}：{t}")
给每条参数挨个编号：第 1 条叫 P03-参1，第 2 条叫 P03-参2……评价同理。
return {"dossier": ..., "product_json": ..., "rules_json": ...}
交出三样东西：给模型读的资料（文字版）、给代码核对用的资料（表格版）、规则库。
为什么用代码不用模型取资料、编号这种事没有任何需要「判断」的地方，用代码 0.1 秒、0 成本、永远不会取错。

B 商品理解Agent

模型节点 · DeepSeek v4-flash · 温度 0.27.2 s · 2,080 token

像商品研究员：读完资料，列出「这个商品值得说的点」和「卖给谁」，而且每一条都要写清楚是从资料哪一条看来的。

提示词里定的规矩（翻译）

  • 只能用资料里的参数和买家原话，不许补常识、产地、排名
  • 每条卖点标 1–3 个编号，编号照抄
  • 只能宣称「批准功效」；买家说的身体变化（感冒少了、精神好了、心脏舒服）不能当卖点
  • 不写极限词，不和别的品牌比
  • 只输出一段固定格式的数据（JSON），不写解释

这次的输出

卖点（7 条） 1 每粒含辅酶Q10 50mg，含量标得清楚　[参1] 2 批准的保健功能是有助于抗氧化　　　[参4] 3 软胶囊个头小，一口就能吞下去　　　[参3 评1] 4 吃着没有怪味，打嗝也没味道　　　　[评2] 5 一天一粒随餐吞服，不容易忘　　　　[参2 评6] 6 瓶盖有防伪码，扫码能查批次　　　　[参6 评5] 7 包装简洁，送长辈也拿得出手　　　　[评7] 人群（3 条） · 经常熬夜加班的上班族　　　　　[评3] · 给爸妈长辈挑日常营养的人　　　　 [评4 评7] · 怕吞大胶囊、在意有没有怪味的人　 [评1 评2]
这一步埋的伏笔卖点守住了：评3 的「没那么累」、评4 的「心脏」都没写成卖点。但人群那一栏引用了评3，写成「经常熬夜加班的上班族」。人群本身不违规，可它把「加班」这个场景带进了下一步。
为什么温度定得低（0.2）这一步要的是准，不是文采。温度越低，模型越老实地照着资料说。

C 卖点溯源校验

代码节点90 ms · 0 token

像核对员：拿着研究员交来的清单，一条一条翻资料，对不上的直接划掉。只有过了这一关的卖点，才会交给写文案的人。

逐条检查的四个问题

  1. 写了出处吗？没写 → 拦
  2. 出处编号在资料里真的存在吗？比如资料只有参1–参6，却写了参9 → 拦
  3. 卖点里有没有没批准的功效词？比如蛋白粉写「抵抗力 up」→ 拦
  4. 有没有医疗用语？比如「护心」→ 拦

这次的结果

商品理解Agent共提炼 7 条卖点 采用 7 条，拦截 0 条 交给下一步的只有这 7 条卖点 + 3 条人群
代码翻译成人话
agent_text = re.sub(r"<think>…</think>", "", agent_text) data = _parse(agent_text)
先把模型的「思考过程」去掉，再把它写的那段数据读成表格。v1.3 换 DeepSeek 时，思考过程混进正文，就是在这里兜底的。
if not refs: reason = "没有标依据"
没写出处 → 记下拦截原因。
bad = [r for r in refs if r not in source]
写了出处，但资料里没有这个编号 → 编的，拦。
eh = _effect_hits(point, rules, approved_cats)
拿规则库里的功效词去卖点里找，找到「没批准的那一类」就拦。批准过的（这里是抗氧化）放过。
if reason: dropped.append(...) else: kept.append(...)
分成两堆：采用 / 拦截。两堆都写进「卖点溯源表」，最后放在报告里给人看。
测试里发现的漏洞它只查卖点，不查人群。所以「经常熬夜加班的上班族」原样流到了下一步。下一版可以让人群也过一遍功效词检查。
为什么要有这一步这是「从源头拦住编造功效」：卖点在写文案之前就过滤掉，后面写得再好也写不出资料里没有的东西。在评测里，它对「无出处、编号不存在、借买家之口宣称功效」三类情况全部拦住（功能用例 F01–F03）。

D 内容生成Agent

模型节点 · DeepSeek v4-flash · 温度 0.78.8 s · 2,111 token

像文案：只拿到核对员放行的卖点清单，按平台的写法写成稿子，再附一张给设计师的主图需求单。

提示词里定的规矩（翻译）

  • 只能用「已核验卖点」，清单外的功效、数据、背书都不写
  • 不写极限词，不比较，不贬低别人
  • 不暗示功效；保健食品只能用批准原文
  • 运营要求和规则冲突时以规则为准，谐音、emoji、场景也不能绕
  • 抖音脚本：30 秒、5–7 个镜头、前 3 秒有钩子；最后附 3 张主图需求

这次的初稿（节选）

【标题】加班党的营养补充，一天一粒 镜头1｜夜晚工位，键盘、外卖杯、台灯 　　口播：加班到晚上十点，今天那粒营养补充，你吃了吗？ 镜头3｜口播：软胶囊个头小……怕吞大胶囊的人也能轻松一点 镜头5｜口播：它批准的保健功能是——有助于抗氧化 　　　　（没写「本品不能代替药物」） 主图1｜每粒50mg
这一步发生了什么「抗疲劳」「对心脏好」都没写，规矩起作用了。但它顺着上一步的人群，用「加班党」「加班到晚上十点」来贴近运营要求，等于用场景暗示「吃了不累」。另外 6 篇保健食品初稿全部漏写了规定声明，这是评测里发现的固定问题。
为什么温度比 B 高（0.7）这一步要文采和变化，温度高一点，写出来不那么像模板。代价是更容易「发挥」，所以后面要有两道合规关卡。

E 合规规则检查

代码节点78 ms · 0 token

像违禁词扫描仪：拿法务的词表把初稿从头扫一遍，命中哪个词、在哪句话里，全部列出来。它只认字，不懂意思。

按顺序扫这几类

  1. 先把法定警示语剔掉（里面有「治疗」二字，不剔会误抓）
  2. 广告法极限词：最好、第一、顶级、100%……
  3. 医疗用语：治疗、降血压、护心、心血管……
  4. 超出批准功效的功效词：这个商品只批了抗氧化，那「抗疲劳、精力充沛、免疫力」都算违规
  5. 贬低竞品：比某大牌、吊打、智商税……
  6. 普通食品不能自称保健品
  7. 保健食品必须有「本品不能代替药物」

这次的结果

命中 1 处 1. [缺少规定声明] 保健食品内容必须包含「本品不能代替药物」 没抓到的：「加班党」「加班到晚上十点」 → 「加班」不在任何词表里，规则看不出这是在暗示抗疲劳
代码翻译成人话
body = text.replace(decl, "") for ph in rules["法定用语"]: body = body.replace(ph, "")
先把规定声明和法定警示语拿掉再扫。v1.3 时「保健食品不是药物，不能代替药物治疗疾病」里的「治疗」被误抓过，这是修复。
for pat in rules["极限词"]: for m in re.finditer(pat, body): add("广告法极限词", m.group(0), m.start())
拿极限词表里的每个词去文里找，找到一个就记一条：哪类、哪个词、前后各 12 个字的上下文。其他几类同理。
if cat in approved_cats: continue
这一类功效是批准过的（P03 的抗氧化），可以写，跳过不扫。
missing_decl = 保健食品 and decl not in text
是保健食品、却没写「本品不能代替药物」，记一处。
为什么规则和模型都要评测里 30 条违规文案：直白的说法（「增强免疫力」「最好喝」）规则 100% 抓到；暗示的说法（「再也没在换季倒下过」）规则 0% 抓到。规则稳定、零成本、法务能直接改，负责明面上的词；意思层面交给下一步的模型。

F 合规审核Agent

模型节点 · DeepSeek v4-flash · 温度 0.243.4 s · 8,978 token

像法务审稿：拿着扫描仪的结果和商品资料，先改掉命中的词，再逐句读一遍，找扫描仪看不出来的「话里有话」，最后交出改好的终稿。

提示词里定的规矩（翻译）

  • 规则命中的每一处必须改掉
  • 再找暗示：标题、正文、话题标签、脚本画面、主图文案逐项看；谐音、emoji、前后对比画面都算
  • 只动有问题的句子，不整段重写
  • 改写后不能保留暗示，不能编资料里没有的信息；拿不准就删
  • 按固定格式输出：审核结论 / 修改说明 / 终稿

这次改了 5 处

标题　加班党的营养补充 → 上班族的日常营养补充 　　　原因：绑定加班人群会暗示抗疲劳 镜头1　加班到晚上十点 → 晚上十点了 　　　原因：去掉加班和产品的因果暗示 镜头3　怕吞大胶囊的人也能轻松一点 → 吞咽不费劲 　　　原因：避免和「大胶囊」比较 镜头5　补上「本品不能代替药物」和不适宜人群 主图1　每粒50mg → 每粒50mg｜本品不能代替药物
它最贵，也最容易过头这一次占了全流程约 68% 的 token、72% 的时间，因为要读整篇初稿和商品资料，再完整写一遍终稿。v1.4 收紧提示词后，违规拦截从 90% 升到 100%，但正常文案也开始被误改（0% → 5.6%）。镜头 1 的「夜晚工位」画面还在，算边界情况，需要人再看一眼。
为什么温度又调回 0.2审核要稳，同一句话今天判违规、明天判通过是不行的。

G 终稿复检与报告组装

代码节点440 ms · 0 token

像终审 + 排版：法务改完的稿子，再用同一台扫描仪扫一遍才放行；然后把终稿、卖点出处、三层审核记录装订成一份报告，交给设计师和品牌部。

它做的事

  1. 从审核Agent 的输出里，切出【终稿】那一段
  2. 用和 E 完全一样的规则再扫一遍
  3. 保健食品还缺声明 → 自动补上
  4. 还有别的命中 → 标「⚠️ 需人工处理」，不放行
  5. 审核Agent 没按格式输出 → 标「⚠️ 未审核初稿」，不放行
  6. 拼报告：状态、终稿、卖点溯源表、合规审核记录

这次的结果

终稿规则复检：无命中 状态：✅ 可交付设计师精修 报告结构 一、终稿（标题、6 个镜头、主图需求单） 二、卖点溯源表（7 条，全部采用） 三、合规审核记录 　① 规则初检 1 处　② 审核Agent 改 5 处　③ 复检 0 处
代码翻译成人话
final = review_text.split("【终稿】", 1)[1]
以「【终稿】」为界，取后面那一段作为终稿。所以 F 的提示词要求终稿必须放在最后。
hits, missing = scan(final, prod, rules)
和 E 用同一个扫描函数、同一份词表。模型改过的东西也要验。
if missing: final += "（本品不能代替药物）"
缺声明这种确定的事，直接用代码补，不再麻烦模型。
if hits: status = "⚠️ 需人工处理" else: status = "✅ 可交付设计师精修"
只要复检还有命中，就不放行，交给人。
为什么要「再扫一遍」v1.1 测试时，运营要求「主打改善便秘」，初稿标题写成「噗噗顺畅✨」，审核Agent 改了正文却漏了标题，终稿仍被标成可交付。加上这一步，模型漏改的明面问题一定会被拦下来。
