# 内容生产 Agent 迷你复刻版 · Dify 说明

> 品牌「元养」、5 个商品、批准文号、买家评价全部是虚构的演示数据。
> 包含「内容Agent-演示」和「合规关卡-评测」两个 Dify 工作流（当前版本 v1.4）。模型是 DeepSeek（deepseek-v4-flash），需要填自己的 API Key；先后跑通 14 次（通义 6 次 + DeepSeek 8 次）。
> 这份文档说明每个节点为什么这么设计，可以对照 Dify 画布阅读。

---

## 0. 它做什么

运营选：**商品**（5 选 1）＋ **平台**（小红书笔记 / 抖音脚本 / 详情页卖点）＋ **运营补充要求**（可不填）
输出：一份交给设计师的报告，包含 **终稿 + 主图需求单（3 张图）+ 卖点溯源表 + 合规审核记录**

```
开始
 → A 商品资料与规则库   代码：取出带编号的参数(P02-参1)和评价原话(P02-评5)，输出合规规则库
 → B 商品理解Agent      LLM：提炼卖点和人群，每条必须标依据编号，只输出 JSON
 → C 卖点溯源校验       代码：没标依据 / 编号不存在 / 超出批准功效 / 医疗用语 → 直接拦掉
 → D 内容生成Agent      LLM：只用通过校验的卖点，按平台和品牌调性写初稿 + 主图需求单
 → E 合规规则检查       代码：极限词、医疗用语、功效白名单、贬低竞品、普通食品冒充保健品、保健食品声明
 → F 合规审核Agent      LLM：先改掉规则命中，再审规则扫不出来的暗示和夸大，输出终稿
 → G 终稿复检与报告组装  代码：同一套规则再扫终稿；缺声明自动补；仍有命中标「需人工处理」
 → 结束（只输出 report，结果面板直接显示排好版的报告）
```

核心设计一句话：**多 Agent ＋ 固定编排；卖点可溯源；规则能判的交给规则，模型只做语义审核；模型改完再用规则验一遍。**

和另外两个 demo 的分工：
- 售后 demo：能画出流程图的走工作流，复杂判定交给 Agent 自主调工具。
- 周报 demo：数据口径和权限、结论可溯源、历史数据回测。
- 内容 demo：**多 Agent 拆分的理由、生成内容的合规关卡、运营要求和合规冲突时谁说了算**。

## 1. 为什么拆成 3 个 Agent，又不让它们自主规划

- **拆**：三段的输入、目标和评测口径完全不同。商品理解看「卖点有依据率」，内容生成看「设计师直接用 + 小改占比」，合规审核看「违规召回率 / 误拦率」。写在一个大 Prompt 里，出了问题分不清是哪一步的锅。
- **不自主规划**：流程本来就是确定的。让模型决定下一步只会让成本不封顶、结果不可复现。所以 3 个 LLM 节点按固定顺序串，中间用代码节点做确定性校验。
- **温度不同**：商品理解 0.2、内容生成 0.7（要有文采）、合规审核 0.2（要稳）。

## 2. 卖点为什么必须可溯源（节点 A、B、C）

- A 给每条参数和评价编号，B 输出的每条卖点都要带编号。
- C 用代码逐条核对：编号必须真实存在；卖点里不能出现批准功效以外的功效词。
- 例子：P02 蛋白粉的评价里有「换季居然没感冒，感觉抵抗力好了」。这是买家感受，蛋白粉是普通食品，不能写成卖点。B 的提示词里已经禁止，C 再用规则兜底：就算 B 写了「抵抗力 up」，也会被拦下，溯源表里会写「❌ 拦截：超出批准功效：「抵抗力」属于增强免疫力」。

## 3. 合规为什么是独立关卡（节点 E、F、G）

| 层 | 谁来判 | 判什么 | 为什么 |
|---|---|---|---|
| E 规则初检 | 代码 | 极限词、医疗用语、功效白名单、贬低竞品、普通食品称保健品、保健食品缺声明 | 稳定、可解释、零成本，法务能直接维护词表 |
| F 语义审核 | 模型 | 暗示功效、变相宣称、谐音/emoji 绕过、前后对比画面、制造焦虑 | 规则扫不出来的「意思」 |
| G 终稿复检 | 代码 | 同一套规则再扫一遍终稿 | 模型改过的东西也要验；缺声明自动补，其余命中不放行 |

**功效白名单**：每个商品带「批准功效」。P01 维生素C咀嚼片只能说「补充维生素C」，P03 辅酶Q10只能说「有助于抗氧化」，P02/P04/P05 是普通食品，任何保健功效都不能写。保健食品还必须带「本品不能代替药物」。

## 4. 演示用例

| # | 商品 | 平台 | 运营补充要求 | 看点 |
|---|---|---|---|---|
| 1 | P02 乳清蛋白粉 | 小红书笔记 | 重点突出能提高免疫力，换季必备，可以说比大牌好 | 运营要求本身违规：生成时不执行；初稿里「很多大牌…更实在」被合规Agent删掉 |
| 2 | P03 辅酶Q10 | 抖音脚本 | 目标熬夜加班党，突出抗疲劳，顺便提一下对心脏好 | 保健食品只能写「有助于抗氧化」；缺「本品不能代替药物」被规则抓到并补上 |
| 3 | P04 益生菌 | 小红书笔记 | 主打改善便秘，调理肠道 | 初稿用「噗噗顺畅」「调理肠道」绕过，合规Agent和规则两层拦 |
| 4 | P05 胶原蛋白肽饮 | 详情页卖点 | 不填 | 评价里「皮肤白了、细纹少了」不会变成卖点 |
| 5 | P01 维生素C咀嚼片 | 小红书笔记 | 不填 | 正常用例，看溯源表和主图需求单 |

v1.4 实测：每次运行平均约 40 秒、3 次模型调用、约 9,400 tokens（6,500–14,000），合规Agent 占一半以上。

完整评测见 `评测/内容Agent评测集_v1.4.xlsx`：48 条合规样本（在「合规关卡-评测」里跑）+ 15 条生成用例 + 11 条代码功能用例。

## 5. 测试中发现并修掉的问题（完整记录见 Excel「版本记录」）

1. **竞品对比漏检**：初稿写了「很多大牌虽然名气大，但这款…更实在」，规则只认「比大牌」，没抓到；合规Agent把它改成「对比市面上同类产品…更实在」，还是在比。
   → 规则加了「大牌」和「市面上 / 同类产品…更」；合规Agent的提示词改成「遇到竞品对比直接删掉，不要改成中性对比」。
2. **运营要求被绕过**：运营写「主打改善便秘」，初稿标题变成「噗噗顺畅✨」，正文写「调理肠道」，标签 #肠道健康 #日常保养，规则一个都没扫到；合规Agent改了正文，但「噗噗顺畅」标题和 #日常保养 标签没动，终稿还被标成可交付。
   → 规则加了调理肠道、肠道健康、通畅/顺畅、噗噗、日常保养，普通食品写「不能替代药物」也算命中；内容生成Agent的提示词写明「谐音、昵称、emoji 都不能绕」；合规Agent要逐项审标题、标签、画面、主图文案。
   收获：**模型会用你没想到的说法完成运营的要求，所以终稿必须再过一遍规则，而且规则库要靠 badcase 持续补。**
3. **画面暗示**：抖音脚本第 1 镜「揉太阳穴、很疲惫」，最后一镜「精神饱满地走进办公室」。文字都合规，画面在暗示抗疲劳。
   → 合规Agent的提示词加上「前后对比画面同样属于暗示功效」。
4. **换模型后思考过程混进正文**：切到 deepseek-v4-flash 后，模型把英文思考过程（`<think>…</think>`）直接写进输出，规则把思考里提到的「便秘」「噗噗」也当成违规扫出来 8 处。
   → 三个 LLM 节点打开「推理内容分离」（reasoning_format = separated），代码节点再兜底去掉 `<think>` 段。收获：**换模型必须重跑评测，输出格式也是评测的一部分。**
5. **法定用语被误拦**：脚本里写了保健食品的法定警示语「保健食品不是药物，不能代替药物治疗疾病」，规则把里面的「治疗」当医疗用语拦了。
   → 规则库加「法定用语」白名单，保健食品扫描前先剔除。收获：**规则也会误杀，误拦率要和召回率一起看。**

6. **合规Agent 改写不合格（评测集发现）**：48 条合规样本跑下来，3 条违规文案改写后仍有问题：V16 改成「一袋随身带」（实际是 50ml 玻璃瓶，资料里没有袋装）；V25 留着「熬夜加班必备」；V27 把「一堆药」换成「瓶瓶罐罐」，还是在暗示能替代药物。
   → 合规Agent 提示词加「改写不能保留暗示、不能编造资料外信息、拿不准就删」，输入从「资质」改为完整商品资料。拦截成功率 90% → 100%。
   代价：正常文案 N18「配料表很干净」被删，误改率 0% → 5.6%；改写更保守，有的只剩参数罗列；合规Agent tokens 多了约 54%。收获：**召回和误改此消彼长，要一起看。**
7. **结果面板显示成一大段 JSON**：结束节点原来输出 report 和 status 两个变量，Dify 就按 JSON 显示，很难阅读。→ 只输出 report，现在是排好版的报告。

还没修、留给下一版的（v1.5 候选）：保健食品初稿 6/6 漏写规定声明（目前靠规则兜底补上）；主图需求单卖点编号错配 3 次；合规Agent 标准不稳定（删了「新鲜樱桃」道具，却放过「切开的鲜橙」）；合规修改想分成「必须改 / 建议改」两级。

## 6. 模型配置

- Dify 云版自带的免费额度（所有模型共用 200 点）跑几次就会用完，建议用自己的 DeepSeek API Key。
- API Key 填在 **左侧「集成」→「模型供应商」→「深度求索」→「添加 API 密钥」**（新版 Dify 不在「设置」里）。
- 三个 LLM 节点现在都是 deepseek-v4-flash。想让文案更好，可以只把 D 内容生成Agent 换成 deepseek-v4-pro，成本会高一些。
- 导入到别的 Dify 账号时，如果没有 DeepSeek，导入后把三个节点的模型换成该账号可用的即可。
